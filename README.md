## 안녕하세요 👋

**데이터를 수집·정제·적재하는 파이프라인을 만들고, 데이터가 정확한지 검증하는 데 집중합니다.**

- **ETL 파이프라인:** 수집 → 정제·검증 → 적재 → 자동화
- **데이터 품질:** 결측·중복 처리 정책을 문서화하고 테스트로 검증
- **자동화:** 스케줄 기반 배치 실행과 CI로 파이프라인 운영
<br>

## 💼 오픈소스 기여

### 1. 매출 데이터 기간 선택 오류 분석 및 제보

edgartools — [Issue #885](https://github.com/dgunning/edgartools/issues/885)

IONQ의 10-Q 공시에서 `get_revenue()`가 최신 분기 매출 대신 전년 동기 매출을 반환하는 데이터 정확성 문제를 발견하고 원인을 분석했습니다.

- **원인:** 컬럼의 위치(index)만으로 기간을 선택해 공시별 컬럼 순서가 다를 때 잘못된 값을 반환
- **분석 및 제안:** 공시 기간의 종료일과 duration 메타데이터를 기준으로 기간을 선택하는 방식 제안
- **결과:** 메인테이너가 관련 조회 함수와 fallback 로직을 수정했으며, [`058648b`](https://github.com/dgunning/edgartools/commit/058648b8a01c510bff318b9be326debc089c17fc)에서 수정하여 `v5.41.0`에 반영

### 2. 운영 현금 흐름 추출 오류 분석 및 제보

edgartools — [Issue #1083](https://github.com/dgunning/edgartools/issues/1083)

Apple의 10-Q 공시에서 `get_operating_cash_flow()`가 운영 현금 흐름을 `None`으로 반환하는 문제를 발견하고, 재현 코드와 검증된 예상값을 제시했습니다.

- **원인:** label 기반 정규식이 Apple의 공시 항목명인 `Cash generated by operating activities`를 인식하지 못함
- **분석:** XBRL 표준 개념은 존재하지만 함수가 해당 개념을 우선 조회하지 않는 문제를 확인
- **결과:** 메인테이너가 XBRL Concept 우선 조회와 label 기반 fallback을 적용한 [PR #1089](https://github.com/dgunning/edgartools/pull/1089)을 병합. 운영 현금 흐름 $82.627B와 이에 의존하는 잉여현금흐름 $78.283B가 정상 추출되도록 수정되어 `v5.52.0`에 반영

## 🚀 주요 프로젝트

### 1. [us-treasury-yield-timeseries-pipeline](https://github.com/QAAAQ123/us-treasury-yield-timeseries-pipeline) — 미국 국채 수익률 시계열 데이터 파이프라인

**시각화 대시보드:** https://qaaaq123.github.io/us-treasury-yield-timeseries-pipeline/

미국 재무부 데이터를 매일 수집해 만기별 수익률과 T10Y2Y·T10Y3M 일드 스프레드 시계열을 적재하고, 시각화 결과를 GitHub Pages에 자동 배포하는 배치 파이프라인입니다.

- **수집:** 미 재무부 국채 금리 XML 수집, 초기 적재와 증분 수집 파이프라인 분리
- **정제·검증:** 휴장일 결측, 만기별 제공 기간, 날짜 중복·변환 실패 등 데이터 처리 정책을 문서화하고 구현
- **적재:** `date` 기본 키 기반 일드 커브·일드 스프레드 CSV 마트 적재
- **자동화:** GitHub Actions 매일 수집 → 데이터 변경 시에만 커밋 → GitHub Pages 재배포
- **테스트:** pytest 단위·통합·E2E 테스트, CI에서 pytest·Ruff 검사
- **사용 기술:** `Python`, `pandas`, `requests`, `Plotly`, `pytest`, `Ruff`, `GitHub Actions`, `GitHub Pages`

### 2. [AlphaDelta](https://github.com/QAAAQ123/AlphaDelta) — SEC 공시 기반 금융 데이터 분석

SEC 공시의 변화(Δ) 분석 서비스를 목표로, 기업·공시·재무 데이터를 수집해 PostgreSQL에 적재하는 데이터 처리 기반을 구축한 프로젝트입니다. (기반 구축 단계에서 중단)

- **수집:** `edgartools` 기반 SEC 기업 정보 DB 동기화, 과거 10-K·10-Q 공시 수집·저장
- **추출:** 손익계산서·현금흐름표 파싱, YTD로 공시되는 현금흐름표를 직전 분기 차감으로 QTD 역산
- **모델링:** Company·Filing·Finance 중심 PostgreSQL 스키마 설계, Alembic 마이그레이션 관리
- **테스트:** VCR 카세트로 실제 SEC 응답을 기록·재생해 Rate Limit 영향 없이 파싱 로직 반복 검증
- **배운 점:** 기업별 비표준 XBRL 태그와 재무제표별 회계 기간 혼재를 다루며 데이터 정합성 검증의 중요성 체감
- **사용 기술:** `Python`, `edgartools`, `PostgreSQL`, `SQLAlchemy`, `Alembic`, `FastAPI`, `pytest`, `pytest-recording`, `Docker`
